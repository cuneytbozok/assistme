Questions you'd otherwise dig for

Ask in plain language. You don't have to know the tables first.

  • Why did this incident change at 14:32?Follows the record's history, then what could have acted on it.
  • Which scripts touch this field?Searches business rules and other scripts, then reads the likely ones in full.
  • Why can't this user see this record?Checks the user's roles against the access rules on the table.
  • Why did last night's Discovery run fail?Reads the logs and the ECC queue around that time.
  • What changed between these two versions of the script?Compares saved versions, line by line.
  • How many P1 incidents did each group get last month?Counts and groups without reading every row.

How it works

  1. You ask

    Ask your question in your AI client. It requests access to one instance and shows you a short code.

  2. You approve

    Click the extension in Chrome. If the code matches, approve it and choose how long the access lasts.

  3. Your AI investigates

    Requests go through your signed-in browser session. Follow-up questions in that chat keep using the access you approved.

You decide what it can reach

Nothing without your approval

Only you can approve access, in Chrome. By default it lasts 4 hours on development and test, and 15 minutes on production, where you also type the host name.

Your password stays in Chrome

Your AI client never sees your password, cookies or session tokens.

It reads as you

What you can see in ServiceNow is all it can see, and your roles and access rules still apply. What it reads goes to the model behind your AI client, so choose one you trust with that data.

Credential tables are blocked

Tables that hold credentials are always blocked. If something can't be read, your AI client is told, so you know an answer may be partial.

Read-only tools, with one exception

There's no tool that creates, changes or deletes anything. But a query may contain a javascript: value or a DYNAMIC filter, as ServiceNow's own list filters do, and ServiceNow runs those as server-side script in your session. A script can do whatever your account can, so a query isn't guaranteed to only read. Keep this in mind before using it on production.

What's included

14 tools

Your AI client uses these for you. Four handle access, and the rest only work after you approve it.

Read
Records, and any field in full, however long
Trace
A record's history, related records, and scripts that mention a field
Understand
Tables and their fields, counts, and comparisons of two records or versions

Documentation research

Optional, and off by default. Searches ServiceNow's published documentation through GitMCP and reads its pages from GitHub, with no key or download. Each result names its release, and your AI client can still use the web or anything else.

2 skills

Optional guidance that adds no access.

Troubleshooting
A method for investigating problems on an instance, such as business rules, flows, Discovery and access rules
Development guide
Scripting, flows, portals and product knowledge, for building on ServiceNow

Adding the skills: upload the zip files in Claude Desktop, install the plugin in Claude Code, or run npm run codex-skills for Codex and Mistral Vibe. See how in the README.

How is this different from the ServiceNow SDK?

They solve different problems. The ServiceNow SDK is for building applications as source code. AssistMe is for finding out what's on an instance and why.

AssistMeServiceNow SDK
Made forInvestigating and understanding an instanceDeveloping and deploying applications
How you use itAsk questions in a chatWork in a code project with TypeScript and command-line tools
Signing inYour existing Chrome sessionIts own sign-in with now-sdk auth, saved on your computer in encrypted form
Reading dataRecords, history, scripts, related records, counts and comparisonsnow-sdk query for read-only table queries
Changing the instanceNo tool for it, apart from the script exception aboveYes: installing and updating applications is its purpose

You can use both. If you build applications, the SDK is the right tool for that. SDK details are from its documentation for version 4.14.

Set it up in four parts

You'll need Node.js 22.18 or newer, Google Chrome, and an instance you can sign in to. A free one is available from developer.servicenow.com.

Terminal
cd ~
git clone https://github.com/cuneytbozok/assistme.git AssistMe
cd AssistMe
npm install
npm run setup

  1. Install

    Run these commands. Setup prints the exact paths for your Mac. Keep the folder where it is afterwards.

  2. Add the extension to Chrome

    Load it from the project folder with Chrome's developer mode.

  3. Add your instance

    Sign in, click the extension, and register the instance. Chrome asks for access to that one site.

  4. Connect your AI client

    Claude Desktop, Claude Code, ChatGPT Desktop (Codex chats only) or Mistral Vibe. The README has the steps for each.

Follow the full steps in the README. Skills and optional documentation research are explained there too.

Where it stands today

This is an early project, and trying it on other setups is the most useful help right now.

Tested

One Mac, with Chrome, one developer instance and an admin account, through Claude Desktop, ChatGPT Desktop and Mistral Vibe.

Not tested yet

Accounts without admin rights, and real Windows PCs. It needs read access to table definitions, which not every account has.

Before you rely on it

Start on a development instance, and check answers you can verify. Records can contain anything, so treat answers like any other research.
